> 문서 버전: **v0.2** (2026-11-25, v0.1 초안 검토·구체화)
> 방식: 화폐·직업·상점은 외부 플러그인, 경제 정책과 서버 전용 콘텐츠는 직접 기획·개발

> 운영 서버 전제: 화이트리스트 지인 서버, 난이도 easy, `keepInventory` 켜짐, Chunky·CoreProtect 보호

## 1. 목표와 원칙

야생 활동(채굴·벌목·농사·사냥·낚시)으로 골드를 벌고, 서버 상점·플레이어 거래·치장 콘텐츠에 쓰는 구조를 추가한다.

1. 야생 플레이의 재미와 아이템 가치를 해치지 않는다. **희귀품은 돈으로 살 수 없다.**
2. 검증된 외부 플러그인을 쓰고, 서버만의 차별점만 직접 만든다.
3. 화폐는 하나(골드, G). 모든 플러그인은 VaultUnlocked를 통해 같은 잔액을 본다.
4. 경제 활동은 선택. 안 해도 야생 플레이에 손해가 없다.
5. **돈이 생기는 곳(공급)은 직업 보상 하나로 시작**하고, 돈이 사라지는 곳(소비)은 상점·치장으로 둔다. 공급원을 늘릴 때는 문서로 근거를 남긴다.
6. 기존 월드·플레이어 데이터와 Travel·Pets·CustomItems를 건드리지 않는다.

확인한 기능 중 기획에 중요한 것:

- **VJobs**: 플레이어가 설치한 블록을 청크 데이터에 기록(재시작 후에도 유지)해 재채굴 보상 없음, 심은 작물은 다 자란 뒤에만 보상, 스포너 몬스터는 보상 0 또는 비율 지정, 실크터치 캐기·설치 반복 보상 없음, AFK 감지, 같은 위치 반복 쿨타임, 크리에이티브 보상 없음, 월드별 비활성화, 경험치 곡선·프레스티지, 저장소 SQLite/MySQL. 최대 직업 수는 `jobs.limit.<n>` 권한.
- **EconomyShopGUI 무료판**: Vault/VaultUnlocked 경제 사용, `/sellall`·`/sellgui`, 게임 안 편집, 권한 그룹별 할인·판매 배율, 계절 가격, 거래 기록 내보내기(`/eshop logs export`). 프리미엄은 GUI 편집기, 명령어 아이템, NBT 커스텀 아이템 등. **상품별 매입 끄기·판매 한도·변동 가격이 무료판에 있는지는 페이지에 안 나와 있어 테스트 서버에서 확인**한다.
- **NexoriaEconomy**: Vault 경제 제공자로 등록, `/pay`(최소 금액 설정), `/baltop`(5분 캐시), Folia/Paper/Purpur, Java 25.

### 2.1 화폐 플러그인 위험과 대안

돈 데이터는 한번 꼬이면 되돌리기 어려워서, 화폐 플러그인만은 신중하게 고른다.

- 26.3을 명시한 다른 후보를 찾아봤지만 마땅치 않다. **EssentialsX**(최신 표기 26.1.2), **ExcellentEconomy**(구 CoinsEngine, 26.2까지, NightCore 필요), **TheNewEconomy**(유지보수 종료)는 모두 26.3 미표기.
- 그래서 **1안: NexoriaEconomy를 테스트 서버에서 검증 후 사용**(아래 체크리스트 통과 시). 저장이 `balances.yml` 한 파일이라 기존 `backup.sh`에 자동 포함되고, 직접 열어볼 수도 있다는 장점은 있다.
- **2안: 자체 `Bank` 플러그인** (`plugins/bank`). VaultUnlocked의 Economy 제공자를 직접 구현(잔액 조회·입금·출금, `/money`, `/pay`, `/baltop`, 거래 로그, SQLite). 이 레포 구조로 2~3일 분량. 버전 업데이트를 우리가 통제할 수 있는 게 가장 큰 장점.
- 어느 쪽이든 다른 플러그인은 VaultUnlocked만 보므로, **나중에 바꿔도 잔액 이전만 하면 된다**(2안을 만들 때 `balances.yml` 가져오기 기능 포함).

NexoriaEconomy 채택 체크리스트 (테스트 서버, 하나라도 실패하면 2안):

1. `/pay` 음수·0·소수점 셋째 자리·잔액 초과·자기 자신·오프라인 대상 → 모두 거부 또는 정상 처리
2. 동시에 두 명이 서로 송금 / 송금 직후 강제 종료(`docker kill`) → 재시작 후 합계 보존
3. VJobs 보상 입금, EconomyShopGUI 구매 출금이 같은 잔액에 반영
4. `balances.yml`이 재시작 후 유지, 손상 시 서버가 잔액을 0으로 덮어쓰지 않음
5. 서버 로그에 경고·스택트레이스 없음

## 3. 시스템 구성

```
플레이어
  ├─ /jobs ...        → VJobs            (돈 공급: 직업 보상)
  ├─ /shop            → EconomyShopGUI   (돈 소비: 구매)
  ├─ /pay, /bal       → NexoriaEconomy   (송금·잔액)
  └─ /economy (1.5단계) → EconomyHub (자체) : 위 명령을 GUI 버튼으로 묶음
                 │
        VaultUnlocked (공통 경제 API)
                 │
        NexoriaEconomy (또는 자체 Bank)  → plugins/<경제>/balances.yml (백업 대상)
```

- 자체 플러그인은 잔액을 따로 저장하지 않고 항상 VaultUnlocked API로 조회·입출금한다.
- VJobs 직업 데이터는 VJobs의 SQLite, 상점 가격은 EconomyShopGUI 설정 파일. 둘 다 `plugins/` 아래라 `backup.sh`에 이미 포함된다.

## 4. 화폐 정책

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 이름 / 표기 | 골드 / `1,234G` | 소수점 없음(정수). 플러그인이 소수점을 쓰면 표시만 정수 |
| 시작 자금 | 0G | |
| 송금 | 허용, 수수료 0%, 최소 1G | 수수료는 인플레이션이 보이면 2~5% 검토 |
| 마이너스 잔액 | 불허 | |
| 사망 시 손실 | 없음 | keepInventory와 일관 |
| 접속 보상·현금 결제 | 없음 | |
| 잔액 상한 | 없음 | 1주차 `/baltop`으로 모니터링 |

### 4.1 경제 기준값

**"직업 활동에 집중한 1시간 ≈ 1,000G"** 를 기준으로 삼는다.

- 직업 보상은 각 직업을 1시간 성실히 했을 때 700~1,200G가 나오도록 잡는다(5장).
- 상점 가격은 "그 아이템을 직접 구하는 데 드는 시간"보다 약간 비싸게 잡는다. 돈은 시간을 아껴 주는 수단이지, 야생보다 효율이 좋으면 안 된다.
- 예: 유리 64개는 모래 캐고 굽는 데 5분 정도 → 128G(약 8분치 수입)

## 5. 직업 시스템 (VJobs)

### 5.1 정책

| 항목 | 값 |
| --- | --- |
| 초기 직업 | 광부, 벌목꾼, 농부, 사냥꾼, 낚시꾼 (5개) |
| 동시 가입 | 최대 2개 (`jobs.limit.2`, 기본 그룹에 부여) |
| 탈퇴·변경 | 가능. 탈퇴한 직업 레벨은 유지(재가입 시 복구)되는지 테스트에서 확인, 안 되면 변경 쿨타임 24시간 |
| 최대 레벨 | 50 |
| 레벨 보너스 | 레벨당 수입 +0.5% (Lv50 = +25%) |
| 능력치 특전 | 없음 (채굴 속도·공격력 등 비활성화) |
| 프레스티지 | 비활성화 (운영 후 검토) |
| 보상 지급 월드 | 오버월드·네더·엔드. 크리에이티브 보상 없음 |
| 스포너 몬스터 | 보상 0% |
| AFK 감지 | 켬 |

### 5.2 보상표

보상은 블록을 **캐는 횟수** 기준이라 행운(Fortune)이 보상을 늘리지 않는다. 플레이어가 설치한 블록은 모두 0G.

**광부** (목표: 심층암 지대 브랜치 마이닝 1시간 ≈ 900G)

| 블록 | 보상 | 블록 | 보상 |
| --- | --- | --- | --- |
| 돌·심층암·응회암 | 0.1G | 석탄 광석 | 3G |
| 네더랙·엔드 돌 | 0G | 구리 광석 | 1.5G |
| 철 광석 | 6G | 금 광석 | 10G |
| 네더 금 광석 | 1G | 레드스톤 광석 | 3G |
| 청금석 광석 | 6G | 네더 석영 광석 | 2G |
| 다이아몬드 광석 | 40G | 에메랄드 광석 | 50G |
| 고대 잔해 | 120G | 심층암 변종 광석 | 일반 광석과 동일 |

계산 근거: 1시간에 다이아 8, 철 30, 레드스톤 40, 청금석 10, 심층암 2,000 정도 → 320+180+120+60+200 ≈ 880G.
네더랙은 효율 V로 즉시 캐지므로 0G (안 그러면 네더 터널 뚫기가 최고 수입원이 됨).

**벌목꾼** (목표: 수동 벌목 1시간 ≈ 800G)

| 블록 | 보상 |
| --- | --- |
| 모든 원목·줄기(진홍·뒤틀린 포함) | 0.8G |
| 나뭇잎 | 0G |
| 거대 버섯 블록 | 0.2G |

묘목을 심어 키운 나무는 "설치한 블록"이 아니므로 보상이 나온다. 나무 농장은 허용(손으로 베야 하므로 시간 대비 정상 수입).

**농부** (목표: 큰 밭 1회 수확 ≈ 300~500G, 시간당 상한은 작물 성장 속도가 결정)

| 작물(다 자란 것만) | 보상 | 작물 | 보상 |
| --- | --- | --- | --- |
| 밀·당근·감자·비트 | 0.5G | 수박·호박 블록 | 0.8G |
| 코코아 | 0.5G | 네더 사마귀 | 0.5G |
| 사탕수수·대나무 | 0.1G | 달콤한 열매 | 0.3G |
| 동물 번식 | 0G | | |

- 피스톤·주민이 수확하면 보상 없음(플레이어가 캔 것만 집계). 자동 농장은 작물 공급용으로는 자유, 돈벌이는 안 됨.
- 사탕수수·대나무는 자라는 속도가 빨라 낮게 잡음. 동물 번식은 밀만 있으면 무한 반복이라 0G.

**사냥꾼** (목표: 일반 사냥 1시간 ≈ 700G)

| 몹 | 보상 | 몹 | 보상 |
| --- | --- | --- | --- |
| 좀비·스켈레톤·거미·크리퍼·드라운드·허스크·스트레이 | 3G | 엔더맨 | 4G |
| 마녀·약탈자·변명자 | 8G | 블레이즈·가스트 | 6G |
| 위더 스켈레톤 | 10G | 피글린 브루트 | 15G |
| 엘더 가디언 | 100G | 워든 | 200G |
| 위더 | 300G | 엔더 드래곤(재소환 포함) | 300G |
| 동물·주민·좀비 피글린 | 0G | 가디언 | 1G |

- 몹 농장(낙하·암실형)은 자연 스폰 + 플레이어 막타라 보상이 나온다. 그래서 일반 몹을 3G로 낮게 잡고, 1주차에 사냥꾼 시간당 수입이 1,500G를 넘으면 일반 몹을 2G로 내린다.
- 좀비 피글린은 금 농장에서 무한히 잡히므로 0G. 가디언도 농장 대상이라 1G.

**낚시꾼** (목표: 바다의 행운·미끼 III 기준 1시간 ≈ 700G)

| 결과 | 보상 |
| --- | --- |
| 물고기 | 4G |
| 보물(인챈트 책·활·낚싯대·안장·이름표·앵무조개 껍데기) | 15G |
| 쓰레기 | 1G |

AFK 낚시(낚싯대 고정)는 AFK 감지로 막는다. 테스트에서 AFK 낚시가 보상을 받으면 낚시꾼 보상을 절반으로 내리고 관리자 감시로 대응.

### 5.3 레벨 경험치

- 보상 1G당 경험치 1. 레벨 n → n+1 필요 경험치 = `100 × n^1.5` (VJobs 곡선 설정 형식에 맞게 근사)
- Lv10 ≈ 10시간, Lv30 ≈ 60시간, Lv50 ≈ 140시간 플레이(직업당). 레벨은 자랑거리 정도의 의미.

## 6. 서버 상점 (EconomyShopGUI)

### 6.1 차익(무한 수익) 방지 규칙

상품을 추가·수정할 때 아래를 모두 만족해야 한다.

1. **매입 가격 ≤ 구매 가격의 25%** (같은 아이템).
2. **조합 차익 금지**: 재료를 사서 만든 결과물의 매입가 ≤ 재료 구매가 합. 반대로 결과물을 사서 분해한 재료의 매입가 합 ≤ 결과물 구매가. (예: 철 블록 ↔ 철 주괴 9개)
3. **제련 차익 금지**: 원석·광석 매입가 ≤ 결과물 매입가가 되지 않게.
4. **자동 생산 가능 자원은 매입하지 않음**: 조약돌·돌·현무암·얼음·모래(가루기)·사탕수수·대나무·호박·수박·켈프·밀·당근·감자·썩은 살점·뼈·실·화약·철(골렘 농장)·금(피글린 농장)·양털·꿀·에메랄드(주민)·청금석·레드스톤(성직자 주민) 등.
5. **주민 거래가와 비교**: 주민에게 싸게 사서 상점에 팔 수 있는 아이템은 매입하지 않는다.

이 규칙 때문에 MVP의 서버 매입은 다이아몬드 하나만 남는다. 돈 공급은 직업 보상이 담당한다.

### 7.2 `/economy` (EconomyHub) 상세

- 의존: `compileOnly` VaultUnlocked API, `plugin.yml`에 `depend: [VaultUnlocked]`, `softdepend: [VJobs, EconomyShopGUI]`
- GUI 27칸: 내 잔액(머리 아이템), 직업 현황(`/jobs` 열기), 상점(`/shop`), 송금 안내(채팅에 `/pay <닉> <금액>` 안내), 부자 순위(`/baltop`), 이용 가이드(책)

### 7.3 `/trade` 요구사항 (3단계)

- 접속자 목록 GUI(기존 `/tpa` GUI 재사용) → 요청 → 30초 내 수락
- 양쪽 4×4 칸 + 골드 입력, 양쪽 "확인" 후 3초 카운트다운 → 확정
- 내용이 바뀌면 양쪽 확인 해제, 거리 제한 없음, 전투 중(Travel의 전투 태그) 불가
- 로그아웃·사망·서버 종료·인벤토리 닫기 → 즉시 취소, 아이템 원래 주인에게 반환(가득 차면 발밑 드롭)
- 골드는 확정 순간에만 출금·입금(잔액 부족 시 거래 취소). 모든 거래는 로그 파일에 기록

## 9. 배포 절차

외부 플러그인도 기존 `scripts/server/install-plugin.sh`로 설치한다. 이 스크립트는 JAR 안의 `plugin.yml` 이름을 읽어 처리하므로 우리 JAR이 아니어도 되고, 백업 → 정지 → 교체 → 시작 → 로드 확인 → 롤백 기록까지 그대로 쓸 수 있다. Chunky·CoreProtect 보호도 그대로 유지된다.

### 9.1 테스트 (로컬)

1. 로컬 테스트 서버(`plugins/custom-items/run/` 등)의 `plugins/`에 외부 JAR 5개를 넣고 실행 → 설정 파일 생성
2. 레포 `server-config/economy/`의 설정을 덮어쓰고 재시작
3. 8장 체크리스트 + 2.1 체크리스트 진행 (TestBot 계정 포함 2인)
4. Travel·Pets·CustomItems와 함께 켜서 로드 오류 없는지 확인

### 9.2 운영

```powershell
# Windows: JAR 업로드
ssh minipc-lan "mkdir -p ~/plugin-staging/economy"
scp .\external\*.jar minipc-lan:~/plugin-staging/economy/
```
```bash
# 미니PC
~/mc-scripts/install-plugin.sh --dry-run ~/plugin-staging/economy/*.jar   # 새 플러그인 5개만 나오는지 확인
~/mc-scripts/install-plugin.sh ~/plugin-staging/economy/*.jar             # 백업 + 설치 + 재시작
# 첫 기동으로 설정 파일이 생긴 뒤, 레포의 설정을 복사하고 한 번 더 재시작
```

- 설정 복사는 `/reload` 없이 재시작으로 반영(기존 원칙 유지).
- 되돌리기: `~/mc-scripts/rollback.sh`(JAR 원복). 경제 데이터만 초기화하려면 백업에서 해당 플러그인 폴더만 복원.
- 오픈 공지: 노션에 명령어표(`/jobs`, `/shop`, `/pay`, `/bal`, `/baltop`, 이후 `/economy`).

### 9.3 설정 파일 관리

- `server-config/economy/<플러그인>/`에 실제 운영 설정을 커밋. 가격 변경은 PR로 남긴다(이 문서 6장과 같이 수정).
- 외부 플러그인 버전은 `server-config/economy/VERSIONS.md`에 기록. 서버 업데이트 시 26.x 지원 여부를 먼저 확인.
