# 야생 서버 경제·직업 시스템 기획서

> 문서 버전: **v0.3** (2026-11-25, v0.2에 결정 사항 반영: 자체 Bank, 기준 수입 10,000원, 서버 매입 보류)
> 방식: 화폐·직업·상점은 외부 플러그인, 경제 정책과 서버 전용 콘텐츠는 직접 기획·개발
> 환경: Paper 26.3 (`26.3-258`) / Java 25 / 이 레포의 Gradle 멀티모듈
> 운영 서버 전제: 화이트리스트 지인 서버, 난이도 easy, `keepInventory` 켜짐, Chunky·CoreProtect 보호

이 문서의 숫자는 모두 **첫 배포용 제안값**입니다. 테스트 서버에서 실제 설정 키로 옮긴 뒤, 운영 1주차 데이터를 보고 조정합니다.

## 1. 목표와 원칙

야생 활동(채굴·벌목·농사·사냥·낚시)으로 돈(원)을 벌고, 서버 상점·플레이어 거래·치장 콘텐츠에 쓰는 구조를 추가한다.

1. 야생 플레이의 재미와 아이템 가치를 해치지 않는다. **희귀품은 돈으로 살 수 없다.**
2. 검증된 외부 플러그인을 쓰고, 서버만의 차별점만 직접 만든다.
3. 화폐는 하나(원). 잔액은 자체 `Bank` 플러그인이 관리하고, 모든 플러그인은 VaultUnlocked를 통해 같은 잔액을 본다.
4. 경제 활동은 선택. 안 해도 야생 플레이에 손해가 없다.
5. **돈이 생기는 곳(공급)은 직업 보상 하나로 시작**하고, 돈이 사라지는 곳(소비)은 상점·치장으로 둔다. 공급원을 늘릴 때는 문서로 근거를 남긴다.
6. 기존 월드·플레이어 데이터와 Travel·Pets·CustomItems를 건드리지 않는다.

확인한 기능 중 기획에 중요한 것:

- **VJobs**: 플레이어가 설치한 블록을 청크 데이터에 기록(재시작 후에도 유지)해 재채굴 보상 없음, 심은 작물은 다 자란 뒤에만 보상, 스포너 몬스터는 보상 0 또는 비율 지정, 실크터치 캐기·설치 반복 보상 없음, AFK 감지, 같은 위치 반복 쿨타임, 크리에이티브 보상 없음, 월드별 비활성화, 경험치 곡선·프레스티지, 저장소 SQLite/MySQL. 최대 직업 수는 `jobs.limit.<n>` 권한.
- **EconomyShopGUI 무료판**: Vault/VaultUnlocked 경제 사용, `/sellall`·`/sellgui`, 게임 안 편집, 권한 그룹별 할인·판매 배율, 계절 가격, 거래 기록 내보내기(`/eshop logs export`). 프리미엄은 GUI 편집기, 명령어 아이템, NBT 커스텀 아이템 등. **상품별 매입 끄기·판매 한도·변동 가격이 무료판에 있는지는 페이지에 안 나와 있어 테스트 서버에서 확인**한다.

### 2.1 화폐는 자체 `Bank` 플러그인으로 (확정)

돈 데이터는 한번 꼬이면 되돌리기 어렵고, 26.3을 명시한 쓸 만한 경제 플러그인이 없다(EssentialsX는 26.1.2, ExcellentEconomy(구 CoinsEngine)는 26.2·NightCore 필요, TheNewEconomy는 유지보수 종료, NexoriaEconomy는 검증 부족). 그래서 처음부터 직접 만든다. 서버 버전을 올릴 때도 우리가 바로 맞출 수 있다.

**`plugins/bank` (플러그인 이름 `Bank`)**

| 항목 | 내용 |
| --- | --- |
| 역할 | VaultUnlocked에 **경제 제공자(Economy provider)** 로 등록. VJobs·EconomyShopGUI·자체 플러그인이 모두 이 잔액을 씀 |
| 연동 | `depend: [VaultUnlocked]`. 구 Vault `Economy` 인터페이스 구현(VJobs·EconomyShopGUI가 쓰는 쪽). VaultUnlocked 2 API는 필요해지면 추가 |
| 금액 | `long` 정수 원. 소수점 입력은 거부, 표시는 `12,340원` |
| 저장 | `plugins/Bank/bank.db` (SQLite, WAL). `accounts(uuid, name, balance, updated_at)`, `transactions(id, time, type, from, to, amount, balance_after, source)` |
| 쓰기 방식 | 잔액은 메모리 캐시가 기준, 변경마다 전용 단일 스레드가 DB에 기록. `/pay`는 보내는 쪽 출금·받는 쪽 입금·로그를 **한 SQL 트랜잭션**으로 처리(중간에 꺼져도 둘 다 반영되거나 둘 다 안 됨) |
| 명령 | `/money` (`/bal`, `/돈`): 내 잔액 · `/money <닉>`: 남의 잔액 · `/pay <닉> <금액>` · `/baltop [쪽]` (10명씩, 1분 캐시) |
| 관리자 | `/bank give·take·set <닉> <금액>`, `/bank log <닉> [쪽]`, `/bank reload` (권한 `bank.admin`, 기본 OP) |
| 송금 규칙 | 최소 10원, 정수만, 잔액 초과·자기 자신·음수·0 거부, 오프라인 대상 허용(서버에 한 번이라도 접속한 플레이어만) |
| 로그 | 모든 입출금을 `transactions`에 기록(직업 보상은 건수가 많으니 1분 단위로 묶어서 1줄). `/bank log`로 조회 |
| 백업 | `plugins/Bank/`가 `backup.sh` 대상에 이미 포함. 배포 중 백업은 서버 정지 상태라 DB가 일관됨 |
| 테스트 | 송금·잔액 부족·동시 송금·재시작 후 유지는 SQLite 메모리 DB로 단위 테스트 |

Bank 완료 체크리스트 (테스트 서버):

1. `/pay` 음수·0·소수점·잔액 초과·자기 자신·없는 닉네임 → 모두 거부
2. 두 명이 동시에 서로 송금 / 송금 직후 강제 종료(`docker kill`) → 재시작 후 총액 보존
3. VJobs 보상 입금, EconomyShopGUI 구매 출금이 같은 잔액에 반영
4. 재시작 후 잔액 유지, `bank.db`가 없거나 깨지면 잔액을 0으로 덮어쓰지 않고 플러그인 비활성화 + 경고
5. 서버 로그에 경고·스택트레이스 없음

## 3. 시스템 구성

```
플레이어
  ├─ /jobs ...        → VJobs            (돈 공급: 직업 보상)
  ├─ /shop            → EconomyShopGUI   (돈 소비: 구매)
  ├─ /money, /pay, /baltop → Bank (자체) (잔액·송금·순위)
  └─ /economy (1.5단계) → EconomyHub (자체) : 위 명령을 GUI 버튼으로 묶음
                 │
        VaultUnlocked (공통 경제 API)
                 │
        Bank (자체, 경제 제공자)  → plugins/Bank/bank.db (백업 대상)
```

- 잔액은 Bank 한 곳에만 저장한다. 다른 자체 플러그인(EconomyHub, Trade)도 Bank를 직접 부르지 않고 VaultUnlocked API로 조회·입출금한다.
- VJobs 직업 데이터는 VJobs의 SQLite, 상점 가격은 EconomyShopGUI 설정 파일. 둘 다 `plugins/` 아래라 `backup.sh`에 이미 포함된다.

### 4.1 경제 기준값

**"직업 활동에 집중한 1시간 ≈ 10,000원"**을 기준으로 삼는다.

- 직업 보상은 각 직업을 1시간 성실히 했을 때 7,000~12,000원이 나오도록 잡는다(5장).
- 상점 가격은 "그 아이템을 직접 구하는 데 드는 시간"보다 약간 비싸게 잡는다. 돈은 시간을 아껴 주는 수단이지, 야생보다 효율이 좋으면 안 된다.
- 예: 유리 64개는 모래 캐고 굽는 데 5분 정도 → 1,280원(약 8분치 수입)

## 5. 직업 시스템 (VJobs)

### 5.1 정책

| 항목 | 값 |
| --- | --- |
| 초기 직업 | 광부, 벌목꾼, 농부, 사냥꾼, 낚시꾼 (5개) |
| 동시 가입 | 최대 2개 (`jobs.limit.2`, 기본 그룹에 부여) |
| 탈퇴·변경 | 가능. 탈퇴한 직업 레벨은 유지(재가입 시 복구)되는지 테스트에서 확인, 안 되면 변경 쿨타임 24시간 |
| 최대 레벨 | 50 |
| 레벨 보너스 | 레벨당 수입 +0.5% (Lv50 = +25%) |
| 능력치 특전 | 없음 (채굴 속도·공격력 등 비활성화) |
| 프레스티지 | 비활성화 (운영 후 검토) |
| 보상 지급 월드 | 오버월드·네더·엔드. 크리에이티브 보상 없음 |
| 스포너 몬스터 | 보상 0% |
| AFK 감지 | 켬 |

### 5.2 보상표

보상은 블록을 **캐는 횟수** 기준이라 행운(Fortune)이 보상을 늘리지 않는다. 플레이어가 설치한 블록은 모두 0원.

**광부** (목표: 심층암 지대 브랜치 마이닝 1시간 ≈ 9,000원)

| 블록 | 보상 | 블록 | 보상 |
| --- | --- | --- | --- |
| 돌·심층암·응회암 | 1원 | 석탄 광석 | 30원 |
| 네더랙·엔드 돌 | 0원 | 구리 광석 | 15원 |
| 철 광석 | 60원 | 금 광석 | 100원 |
| 네더 금 광석 | 10원 | 레드스톤 광석 | 30원 |
| 청금석 광석 | 60원 | 네더 석영 광석 | 20원 |
| 다이아몬드 광석 | 400원 | 에메랄드 광석 | 500원 |
| 고대 잔해 | 1,200원 | 심층암 변종 광석 | 일반 광석과 동일 |

계산 근거: 1시간에 다이아 8, 철 30, 레드스톤 40, 청금석 10, 심층암 2,000 정도 → 3,200+1,800+1,200+600+2,000 ≈ 8,800원.
네더랙은 효율 V로 즉시 캐지므로 0원 (안 그러면 네더 터널 뚫기가 최고 수입원이 됨).

**벌목꾼** (목표: 수동 벌목 1시간 ≈ 8,000원)

| 블록 | 보상 |
| --- | --- |
| 모든 원목·줄기(진홍·뒤틀린 포함) | 8원 |
| 나뭇잎 | 0원 |
| 거대 버섯 블록 | 2원 |

묘목을 심어 키운 나무는 "설치한 블록"이 아니므로 보상이 나온다. 나무 농장은 허용(손으로 베야 하므로 시간 대비 정상 수입).

**농부** (목표: 큰 밭 1회 수확 ≈ 3,000~5,000원, 시간당 상한은 작물 성장 속도가 결정)

| 작물(다 자란 것만) | 보상 | 작물 | 보상 |
| --- | --- | --- | --- |
| 밀·당근·감자·비트 | 5원 | 수박·호박 블록 | 8원 |
| 코코아 | 5원 | 네더 사마귀 | 5원 |
| 사탕수수·대나무 | 1원 | 달콤한 열매 | 3원 |
| 동물 번식 | 0원 | | |

- 피스톤·주민이 수확하면 보상 없음(플레이어가 캔 것만 집계). 자동 농장은 작물 공급용으로는 자유, 돈벌이는 안 됨.

## 6. 서버 상점 (EconomyShopGUI)

### 6.1 차익(무한 수익) 방지 규칙

MVP는 서버 매입(플레이어가 서버에 파는 것)이 없어서 차익이 생길 수 없다. 아래 규칙은 **나중에 매입을 추가할 때** 반드시 지킨다.

1. **매입 가격 ≤ 구매 가격의 25%** (같은 아이템).
2. **조합 차익 금지**: 재료를 사서 만든 결과물의 매입가 ≤ 재료 구매가 합. 반대로 결과물을 사서 분해한 재료의 매입가 합 ≤ 결과물 구매가. (예: 철 블록 ↔ 철 주괴 9개)
3. **제련 차익 금지**: 원석·광석 매입가 ≤ 결과물 매입가가 되지 않게.
4. **자동 생산 가능 자원은 매입하지 않음**: 조약돌·돌·현무암·얼음·모래(가루기)·사탕수수·대나무·호박·수박·켈프·밀·당근·감자·썩은 살점·뼈·실·화약·철(골렘 농장)·금(피글린 농장)·양털·꿀·에메랄드(주민)·청금석·레드스톤(성직자 주민) 등.
5. **주민 거래가와 비교**: 주민에게 싸게 사서 상점에 팔 수 있는 아이템은 매입하지 않는다.

이 규칙을 적용하면 매입 후보는 다이아몬드 같은 재생 불가 자원 정도만 남는다. 돈 공급은 직업 보상이 담당한다.

### 6.2 판매 제외 (돈으로 못 사는 것)

다이아몬드·에메랄드·네더라이트(관련 전부), 다이아·네더라이트 장비, 인챈트 책, 경험치 병, 황금 사과·마법이 부여된 황금 사과, 불사의 토템, 겉날개, 셜커 상자·껍데기, 스포너·스폰 알, 네더의 별·신호기, 트라이던트, 철갑 껍데기, 엔더 진주·엔더의 눈, 커스텀 고성능 장비.

### 7.2 `/economy` (EconomyHub) 상세

## 9. 배포 절차

Bank는 다른 자체 플러그인처럼 `deploy.ps1 -Plugin bank`로, 외부 플러그인도 같은 `scripts/server/install-plugin.sh`로 설치한다. 이 스크립트는 JAR 안의 `plugin.yml` 이름을 읽어 처리하므로 우리 JAR이 아니어도 되고, 백업 → 정지 → 교체 → 시작 → 로드 확인 → 롤백 기록까지 그대로 쓸 수 있다. Chunky·CoreProtect 보호도 그대로 유지된다.

### 9.1 테스트 (로컬)

1. `.\gradlew :plugins:bank:runServer`로 뜨는 테스트 서버(`plugins/bank/run/`)의 `plugins/`에 외부 JAR 4개(VaultUnlocked·VJobs·EconomyShopGUI·LuckPerms)를 넣고 실행 → 설정 파일 생성
2. 레포 `server-config/economy/`의 설정을 덮어쓰고 재시작
3. 8장 체크리스트 + 2.1 체크리스트 진행 (TestBot 계정 포함 2인)
4. Travel·Pets·CustomItems와 함께 켜서 로드 오류 없는지 확인

### 9.2 운영

```powershell
# Windows: 1) Bank 먼저 업로드만 (설치는 외부 플러그인과 한 번에)
.\scripts\deploy.ps1 -Plugin bank -SshHost minipc-lan -UploadOnly
# 2) 외부 JAR 업로드
ssh minipc-lan "mkdir -p ~/plugin-staging/economy"
scp .\external\*.jar minipc-lan:~/plugin-staging/economy/
```
```bash
# 미니PC
~/mc-scripts/install-plugin.sh --dry-run ~/plugin-staging/bank-*.jar ~/plugin-staging/economy/*.jar   # 새 플러그인 5개만 나오는지 확인
~/mc-scripts/install-plugin.sh ~/plugin-staging/bank-*.jar ~/plugin-staging/economy/*.jar             # 백업 + 설치 + 재시작
```

- 설정 복사는 `/reload` 없이 재시작으로 반영(기존 원칙 유지).
- 되돌리기: `~/mc-scripts/rollback.sh`(JAR 원복). 경제 데이터만 초기화하려면 백업에서 해당 플러그인 폴더만 복원.
- 오픈 공지: 노션에 명령어표(`/jobs`, `/shop`, `/money`, `/pay`, `/baltop`, 이후 `/economy`).

### 9.3 설정 파일 관리

- `server-config/economy/<플러그인>/`에 실제 운영 설정을 커밋. 가격 변경은 PR로 남긴다(이 문서 6장과 같이 수정).
- 외부 플러그인 버전은 `server-config/economy/VERSIONS.md`에 기록. 서버 업데이트 시 26.x 지원 여부를 먼저 확인.

## 10. 1주차 모니터링

매일 한 번 확인하고 2단계 조정의 근거로 쓴다.

| 지표 | 보는 곳 | 조정 기준 |
| --- | --- | --- |
| 직업별 시간당 수입 | VJobs 통계 또는 직접 측정 | 목표(7,000~12,000원) 대비 ±50% 벗어나면 보상 수정 |
| 총 통화량·상위 잔액 | `/baltop` | 1위가 2위의 5배 이상이면 원인 조사 |
| 상점 판매 상위 품목 | `/eshop logs export` | 안 팔리는 카테고리는 가격 인하 |
| 악용 의심 | CoreProtect, 직업 수입 급증 | |

## 11. 첫 배포 완료 기준

- 모든 플레이어가 `/money`로 잔액 확인, `/pay`로 송금 가능 (Bank)
- 직업 가입(최대 2개) 후 야생 활동으로 보상 수령
- `/shop`에서 구매 가능, 6.2 품목은 상점에 없음, 서버 매입은 막혀 있음
- 재시작 후 잔액·직업 레벨 유지
- 8장 체크리스트 통과
- Travel·Pets·CustomItems·Chunky·CoreProtect 정상
